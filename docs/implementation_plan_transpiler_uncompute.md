# Implementation Plan: Transpiler-Based Uncomputation (MVP)

**PRD:** `docs/prd_transpiler_uncompute.md`
**Principles:** `docs/01_principles.md` (esp. B1b, B6, P9)
**Post-MVP:** `docs/roadmap_transpiler_post_mvp.md`
**Approach:** Modular, strict TDD. Each module has a LOC budget of **≤ 300 lines** across all files it touches (including its own tests). Each module lands as one commit; each ships with its tests green.

---

## Goal (MVP)

End-to-end pipeline for **one** pattern:

```cpp
// Input (src/demo.cpp)
void demo(qbool a, qbool b) { qbool tmp = a | b; }

// Transpiler output (build/sturm_gen/src/demo.cpp)
// AUTO-GENERATED by sturm-transpile — do not edit
void demo(qbool a, qbool b) {
    qbool tmp = a | b;
    uncompute_or(tmp, a, b);
}
```

Compiled with `STURM_AUTO_UNCOMPUTE=OFF`, the generated binary's gate stream must equal a hand-written reference that uses explicit `uncompute_or`.

## TDD Discipline

Every module follows: **red → green → refactor**.

1. Write the test file(s) listed under "Tests" first. They must fail (compile error, link error, or assertion failure) before implementation starts.
2. Implement the minimum code to make them pass.
3. Refactor if needed; re-run tests.
4. Do not merge a module whose tests are not green on both `-DSTURM_AUTO_UNCOMPUTE=ON` and `-DSTURM_AUTO_UNCOMPUTE=OFF` CMake configurations (once M1 lands; before M1, only the default build matters).

Tests use the project's plain-assert harness (`tests/test_qbool.cpp` is the reference pattern: `CHECK(cond)` macro, `tests_run` / `tests_pass` counters, `printf("PASS: %d/%d", ...)` summary, `add_test` in the appropriate `CMakeLists.txt`). No googletest, no catch2.

### M1: CMake flags

**Goal:** Introduce the two build flags the rest of the plan hangs off.

**Files touched:**

**Changes:**

```cmake
endif()
```

**Tests:** none (pure wiring — exercised by M2/M3/M4 builds). A CI smoke matrix in the Verification section below confirms both configurations build.

**LOC budget:** ~20 lines (CMake only).

**Acceptance:**
- Default `cmake ..` still configures identically to before M1 (flag defaults preserve legacy behavior).
- `cmake -DSTURM_AUTO_UNCOMPUTE=OFF ..` configures and `-DSTURM_AUTO_UNCOMPUTE=1` is absent from `compile_commands.json`.
- `cmake -DSTURM_TRANSPILE=ON ..` attempts to enter `transpiler/` (which does not yet exist — expect configure error until M4 lands; this is intentional and documented).

### M2: Destructor gate on `STURM_AUTO_UNCOMPUTE`

**Goal:** When the flag is OFF, `~qint_t<W>()` only releases qubits. The destructor no longer emits inverse gates and no longer consults the `WhenCapture` thread-local.

**Files touched:**
- `include/sturm/qtypes/qint_core.hpp` — wrap the `WhenCapture`-deferral block (lines 171-193) and the Strategy-B inverse-emission block (lines 196-201) with `#ifdef STURM_AUTO_UNCOMPUTE`. Qubit release (lines 207-213) stays unconditional. `qbool` inherits through its default destructor — no change needed there.

**Shape of the diff:**
```cpp
~qint_t() {
#ifdef STURM_BACKEND_ENABLED
#  ifdef STURM_AUTO_UNCOMPUTE
    // WhenCapture deferral — unchanged body
    if (detail::when_capture_defer_fn && owning_) { /* ... */ }
    // Step 1: emit semantic inverse — unchanged body
    if (uncompute_.tag != uncompute_op::kind::NONE) { /* ... */ }
#  endif // STURM_AUTO_UNCOMPUTE
#endif // STURM_BACKEND_ENABLED
    // Step 2: release qubits — unconditional
    if (owning_) { for (int idx : qubits) if (idx >= 0) QubitPool::instance().release(idx); }
}
```

**Tests (write first):** `tests/test_destructor_gate.cpp` — one binary compiled twice (once with flag ON, once with flag OFF) via two CMake targets:
- `test_destructor_gate_autoon` (flag ON) — checks that destructing a `qbool` carrying a non-`NONE` uncompute op emits the expected inverse gates to a recording sink.
- `test_destructor_gate_autooff` (flag OFF) — identical setup, asserts the sink captures **zero** gates from the destructor, and that `QubitPool` reflects the released qubit.

Both configurations must also pass a shared regression: a non-owning `qbool` (`make_non_owning`) releases nothing in either mode.

**LOC budget:** ~15 LOC change in `qint_core.hpp`; ~180 LOC across the two test drivers + shared helper (~200 LOC total).

**Acceptance:**
- Under `-DSTURM_AUTO_UNCOMPUTE=OFF`, destructor runs release-only. Recording sink captures zero gates from destructor.
- Under `-DSTURM_AUTO_UNCOMPUTE=ON`, destructor behaves exactly as before (pre-M2) — every existing `tests/` binary still green. No test under `tests/` is removed or modified.
- Pool release count matches owning qubit count in both modes.

### M3: `uncompute_or` free-function API

**Goal:** Ship the single inverse the MVP needs. Establish the `uncompute_api.hpp` header as the new landing zone for all future inverse free functions (Phases A-D in the post-MVP roadmap will add more).

**Files created:**
- `include/sturm/uncompute/uncompute_api.hpp` — header with declarations and doc. MVP declares exactly:
  ```cpp
  namespace sturm {
  /// Uncompute an inclusive-OR ancilla produced by `r = a | b`.
  /// Emits the inverse of the forward OR decomposition (CCX of a,b → r then
  /// X of a,b) against the active sink. Does not release any qubits.
  /// Preconditions: r, a, b all live; r owning; a and b unchanged since the
  /// forward OR.
  void uncompute_or(qbool& r, const qbool& a, const qbool& b);
  } // namespace sturm
  ```
- `src/sturm/uncompute/uncompute_api.cpp` — implementation. Uses existing primitives (`execute_gate` / `current_sink()`) with the same gate sequence as the forward-OR adjoint already present in `uncompute_op.hpp` `BITWISE_SELF` (kind=1, OR) at lines 237-271. Reuse that logic; do not re-derive. Keep the body small — call into a shared helper if the copy-out grows past ~60 LOC.

**Tests (write first):** `tests/test_uncompute_or.cpp`
- Forward-then-inverse returns the ancilla to `|0⟩`: set up `a` and `b` superposed, compute `r = a | b`, call `uncompute_or(r, a, b)`, assert `r` qubit is at `|0⟩` under a state-vector check (direct-mode sink with Orkan backend) or equivalent gate-count/pattern check under circuit mode.
- Classical-classical case: `a` and `b` both classical, `uncompute_or` emits zero gates (classicality specialization in the existing primitives handles this — the test confirms no regression when callers pass classical operands).
- Mixed case: one quantum, one classical — emits the right subset (X on the classical-1 bit to undo the forward X; CNOT on the quantum bit). Mirrors the four-quadrant classical-folding rules already in `bit_proxy.hpp`.

**LOC budget:** header ~50; impl ~90; tests ~140. **Total ~280.**

**Acceptance:**
- All three tests pass under `-DSTURM_AUTO_UNCOMPUTE=OFF` (the target runtime configuration for the transpiler).
- They also pass under `-DSTURM_AUTO_UNCOMPUTE=ON`, because `uncompute_or` is an explicit free-function call that does not interact with the destructor path.
- Header-only consumers can include `<sturm/sturm.hpp>` and call `uncompute_or` with no additional include.
- `uncompute_api.hpp` is added to the umbrella include `include/sturm/sturm.hpp` (or wherever the current fan-out lives).

### M5: Skip marker + idempotency header

**Goal:** Two orthogonal pass-through cases.
1. **Skip marker** — a file whose first non-blank, non-whitespace line is `// sturm-transpile: skip` is copied verbatim. Transpilation is suppressed.
2. **Idempotency header** — generated output starts with `// AUTO-GENERATED by sturm-transpile — do not edit\n// Source: <original path>`. A file whose first line is the AUTO-GENERATED sentinel is also treated as pass-through. Running the transpiler on its own output produces a byte-identical file.

**Files created:**
- `transpiler/include/sturm/transpile/skip.hpp` — declares `bool should_skip(std::string_view head)` and `std::string idempotency_header(std::string_view source_path)`.
- `transpiler/src/skip.cpp` — implementation. Pure string functions; no LibTooling dependency.
- `transpiler/src/main.cpp` — updated to read the first ~512 bytes, call `should_skip`, short-circuit to verbatim copy on hit. For non-skipped files, the emitter (M9) will prepend `idempotency_header` to the output.

**Test fixtures:**
- `transpiler/tests/fixtures/skip_marker.cpp` — 5-line file whose first content line is the marker; body deliberately includes something the matcher would otherwise trigger on (`qbool tmp = a | b;`).
- `transpiler/tests/fixtures/skip_marker.expected.cpp` — byte-identical copy.
- `transpiler/tests/fixtures/already_generated.cpp` — synthetic file with the AUTO-GENERATED header followed by a full expected output.
- `transpiler/tests/fixtures/already_generated.expected.cpp` — byte-identical copy.

**Tests (write first):** `transpiler/tests/test_skip.cpp`
- Unit: `should_skip("// sturm-transpile: skip\n...")` → `true`.
- Unit: `should_skip("// AUTO-GENERATED by sturm-transpile — do not edit\n...")` → `true`.
- Unit: `should_skip("#include <sturm/sturm.hpp>")` → `false`.
- Unit: `should_skip("   \n\n// sturm-transpile: skip\n")` → `true` (leading blank lines tolerated).
- Integration: end-to-end driver run on both fixtures produces byte-identical output against their `.expected.cpp`.

**LOC budget:** header ~20; impl ~60; main.cpp delta ~15; tests ~70; fixtures ~40. **Total ~205.**

**Acceptance:**
- Both unit and integration tests green.
- PRD acceptance criterion #5 (idempotency) and #6 (skip marker) are satisfied at the driver level.

### M6: Quantum IR

**Goal:** The data structures the matcher fills and the uncompute pass / emitter read. Flat list of operations with scope markers and explicit def/use edges (the default shape noted in the PRD's Open Questions).

**Files created:**
- `transpiler/include/sturm/transpile/qir.hpp` — defines:
  ```cpp
  namespace sturm::transpile {

  enum class QOpKind { OR /* , AND, XOR, NOT, ... added per post-MVP phases */ };

  struct QValueRef {             // symbolic reference to a named qbool/qint in user code
      std::string name;          // e.g. "a", "tmp"
      clang::SourceLocation decl_loc;  // for diagnostics + emitter insertion points
  };

  struct QOperation {
      QOpKind kind;
      QValueRef result;          // the produced intermediate (for expression forms)
      std::vector<QValueRef> operands;
      clang::SourceRange stmt_range;   // the full statement, used by emitter
  };

  struct QScope {
      clang::SourceLocation open_brace;
      clang::SourceLocation close_brace;
      std::vector<QOperation> ops;     // in source order
  };

  // Top-level container: one per translation unit.
  struct QUnit {
      std::vector<QScope> scopes;      // ordered by open_brace location
  };

  // Small helpers for the pass + emitter.
  bool operator==(const QValueRef&, const QValueRef&);
  std::string dump(const QUnit&);      // debugging; also used by tests
  } // namespace sturm::transpile
  ```
- `transpiler/src/qir.cpp` — implements `operator==` and `dump()`. No AST dependencies beyond the Clang source-location types.
- `transpiler/tests/test_qir.cpp` — construct a small `QUnit` manually, assert `dump()` round-trips deterministically; assert `operator==` on `QValueRef`.

**LOC budget:** header ~140; impl ~70; tests ~60. **Total ~270.**

**Acceptance:**
- Tests pass.
- Header is self-contained (includes only `<clang/Basic/SourceLocation.h>`, `<string>`, `<vector>`).
- `dump()` output is documented as stable — the M7/M8 tests compare against golden strings produced by this function, so a change in `dump()` format is a breaking change.

### M7: AST matcher — `qbool tmp = a | b`

**Goal:** One Clang `ASTMatcher` that fires on a `VarDecl` whose initializer is a call to `operator|(const qbool&, const qbool&)`. On each match, synthesize one `QOperation{kind=OR, result=<var>, operands=[a, b], stmt_range=<decl range>}` and append it to the enclosing `QScope` in the `QUnit`.

**Files created:**
- `transpiler/include/sturm/transpile/matcher.hpp` — declares `void register_or_matcher(clang::ast_matchers::MatchFinder& finder, QUnit& unit)`.
- `transpiler/src/matcher.cpp` — defines:
  - A `MatchCallback` subclass holding a `QUnit*`. Its `run(const MatchResult&)`:
    1. Extract the matched `VarDecl` and its `CXXOperatorCallExpr` initializer.
    2. Verify the operator is `|` and both operand types are `sturm::qbool` (`hasType(cxxRecordDecl(hasName("qbool")))`).
    3. Resolve the enclosing `CompoundStmt` → locate or create the `QScope` in `*unit`.
    4. Build `QOperation` with `result.name = VarDecl->getName()`, operand names from the referenced `DeclRefExpr`s, `stmt_range = VarDecl->getSourceRange()`.
    5. Append to the scope.
  - A `register_or_matcher` helper that builds the matcher expression and hooks up the callback:
    ```cpp
    auto pattern = varDecl(
        hasType(cxxRecordDecl(hasName("qbool"))),
        hasInitializer(cxxOperatorCallExpr(
            hasOverloadedOperatorName("|"),
            argumentCountIs(2),
            hasArgument(0, declRefExpr().bind("lhs")),
            hasArgument(1, declRefExpr().bind("rhs"))))
    ).bind("var");
    ```

**Tests (write first):** `transpiler/tests/test_matcher.cpp`
- Uses `clang::tooling::runToolOnCodeWithArgs` with the repo's `include/` on the include path.
- Positive case: input source `qbool demo(qbool a, qbool b) { qbool tmp = a | b; return tmp; }` → `QUnit` has one scope with one `QOperation{kind=OR, result.name="tmp", operands=[{a}, {b}]}`.
- Negative cases (matcher must NOT fire):
  - `qbool tmp = a & b;` (wrong operator).
  - `qint tmp = a | b;` (wrong result type — out of MVP scope; matcher is narrow).
  - `qbool tmp = foo(a, b);` (not operator|).
  - `bool tmp = ...;` (classical — not a qbool VarDecl).
- Nested-scope case: two siblings `{ qbool t = a|b; } { qbool t = a|b; }` produce two distinct `QScope`s with one op each.

**LOC budget:** header ~30; impl ~160; tests ~100. **Total ~290.**

**Acceptance:**
- All tests pass.
- The matcher is strictly scoped to the MVP pattern. Widening to other operators / binary forms is a Phase A/B deliverable per the roadmap, not this module.
- Source locations captured in `stmt_range` round-trip through `clang::SourceManager` without loss (tested by reading the captured range back as text and asserting it equals the original declaration).

### M8: Uncompute synthesis pass

**Goal:** Given a `QUnit` from M7, produce a list of `UncomputeInsertion` records describing **what to insert and where**. Pass-only; no AST mutation yet.

**Files created:**
- `transpiler/include/sturm/transpile/uncompute_pass.hpp`:
  ```cpp
  namespace sturm::transpile {

  struct UncomputeInsertion {
      clang::SourceLocation insert_before;  // the closing '}' of the scope
      std::string code;                     // e.g. "    uncompute_or(tmp, a, b);\n"
  };

  std::vector<UncomputeInsertion> synthesize(const QUnit& unit);
  } // namespace sturm::transpile
  ```
- `transpiler/src/uncompute_pass.cpp` — for each `QScope` in `unit`, walk its `ops` in reverse order; for each `QOperation{kind=OR}`, emit one `UncomputeInsertion` whose `code` is:
  ```
  "    uncompute_or(<result>, <operands[0]>, <operands[1]>);\n"
  ```
  with `insert_before = scope.close_brace`. LIFO order is critical — the reverse-iteration discipline is what the whole PRD is about.

**Tests (write first):** `transpiler/tests/test_uncompute_pass.cpp`
- Single op: one scope, one OR op → one `UncomputeInsertion` with correct code.
- Two ops in one scope (this is ahead of MVP coverage but the pass must already be correct): `tmp0 = a|b; tmp1 = c|d;` → two insertions, with the `tmp1` uncompute ordered *first* (LIFO).
- Two scopes with one op each → two insertions, each anchored to its own scope's close brace.

**LOC budget:** header ~30; impl ~80; tests ~80. **Total ~190.**

**Acceptance:**
- Tests pass.
- Unit test comparing LIFO order uses a synthetic `QUnit` — no Clang invocation — so it runs in microseconds and catches ordering regressions precisely.

### M9: C++ emitter

**Goal:** Given the original source file and the `UncomputeInsertion` list from M8, use `clang::Rewriter` to produce the transpiled source, prepend the idempotency header from M5, and write it to `<output-dir>/<relpath>`.

**Files created:**
- `transpiler/include/sturm/transpile/emitter.hpp`:
  ```cpp
  namespace sturm::transpile {
  void emit(const clang::SourceManager& sm,
            clang::Rewriter& rw,
            const std::vector<UncomputeInsertion>& insertions,
            std::string_view source_path,
            std::string_view output_dir);
  } // namespace sturm::transpile
  ```
- `transpiler/src/emitter.cpp` — for each insertion in the input list, call `rw.InsertTextBefore(insert.insert_before, insert.code)`. Then serialize the rewritten buffer, prepend `idempotency_header(source_path)`, and write via the `io.cpp` helper from M4.
  - One subtle point already solved: the insertions list from M8 is already in LIFO order per scope, but insertions are location-anchored, not order-sensitive — `Rewriter` handles interleaving fine. Document this explicitly in a comment.
- `transpiler/src/main.cpp` (update) — compose the full pipeline: parse → run `MatchFinder` with the M7 matcher → call `synthesize` → call `emit`.

**Tests (write first):** `transpiler/tests/test_emitter.cpp`
- Golden: input source `"void demo(qbool a, qbool b) { qbool tmp = a | b; }\n"` + one insertion at the scope's closing brace → output source equals:
  ```
  // AUTO-GENERATED by sturm-transpile — do not edit
  // Source: <path>
  void demo(qbool a, qbool b) { qbool tmp = a | b;
      uncompute_or(tmp, a, b);
  }
  ```
  Exact whitespace TBD during implementation (use Clang's SourceLocation-to-column conversion); the golden file records the canonical form.
- Idempotency: emit to a file, feed the result back through the pipeline; M5's skip path short-circuits and the second output is byte-identical to the first.

**LOC budget:** header ~40; impl ~120 (Rewriter + header prepend + write-out); main.cpp delta ~30; tests ~80. **Total ~270.** If the impl unexpectedly balloons past 200 LOC (e.g. due to whitespace/indentation fixups that turn into their own helper), split into **M9a** = `emitter.hpp/.cpp` + unit test, **M9b** = `main.cpp` pipeline composition + integration test, before merging.

**Acceptance:**
- Snapshot golden test passes (byte-exact match).
- Idempotency test passes.
- PRD acceptance criteria #1, #2, #5 are met at this point.

### M10: `add_quantum_executable()` CMake helper

**Goal:** Build-system glue that routes sources through `sturm-transpile` when `STURM_TRANSPILE=ON`.

**Files created:**
- `cmake/SturmTranspile.cmake`:
  ```cmake
  function(add_quantum_executable target)
      set(generated_sources)
      foreach(src ${ARGN})
          if(STURM_TRANSPILE)
              get_filename_component(abs_src ${src} ABSOLUTE)
              file(RELATIVE_PATH rel_src ${CMAKE_SOURCE_DIR} ${abs_src})
              set(gen_src ${CMAKE_BINARY_DIR}/sturm_gen/${rel_src})
              add_custom_command(
                  OUTPUT ${gen_src}
                  COMMAND sturm-transpile ${abs_src}
                      --output-dir ${CMAKE_BINARY_DIR}/sturm_gen
                  DEPENDS ${abs_src} sturm-transpile
                  COMMENT "sturm-transpile ${rel_src}")
              list(APPEND generated_sources ${gen_src})
          else()
              list(APPEND generated_sources ${src})
          endif()
      endforeach()
      add_executable(${target} ${generated_sources})
      target_link_libraries(${target} PRIVATE sturm)
  endfunction()
  ```
- Root `CMakeLists.txt` — `include(cmake/SturmTranspile.cmake)` after the flags block from M1.

## Risk Areas

1. **LibTooling CMake discovery.** Clang/LLVM versions 14-18 differ in module naming (`clangTooling` vs `clang-cpp`) and in whether `ClangConfig.cmake` ships in the distro packages. M4 must document the supported Clang range and fail with a clear message on mismatch.
2. **Template-heavy user code.** The matcher in M7 uses `hasName("qbool")` — which resolves to `sturm::qbool` = `sturm::qint_t<1>` via typedef. Verify the matcher fires whether the user declares `sturm::qbool tmp` or `qint_t<1> tmp` (MVP covers only the former; wider coverage is Phase A).
3. **Source locations across macros.** `WHEN(expr)` is a macro — source locations inside it are spelling vs expansion. MVP does not touch WHEN (that's Phase F), but early tests should use input files free of macros to avoid surprises. Add a fixture comment reminding the reader.
4. **Rewriter insertion at `close_brace`.** Clang's `Rewriter::InsertTextBefore(loc, text)` at a `}` is well-supported; however, if the closing brace is on the same line as other tokens, the whitespace in the emitted code may look odd. M9's golden fixture records the canonical form — if it looks ugly, pretty-print tweaks are an acceptable next iteration (not an MVP blocker).
5. **Non-owning `qbool` operands.** `qbool::make_non_owning` returns a view with `qubits[0] >= 0` but `owning_ = false`. The matcher in M7 should not special-case these (they are still `DeclRefExpr`s at the AST level). But the runtime `uncompute_or` in M3 must not over-release. M3's tests already cover this — verify once more when M12 wires the pieces together.
6. **Pool double-release after move.** The existing `~qint_t` sets `qubits.fill(-1)` on the `WhenCapture` deferral path (line 189) to prevent double-release. Under M2's `STURM_AUTO_UNCOMPUTE=OFF` branch, the deferral is skipped entirely, so that guard is moot; just confirm no other code path creates aliasing.
7. **`.cpp` vs `.hpp` split for `uncompute_api`.** M3 puts the implementation in a `.cpp` file. If `include/sturm/sturm.hpp` is strictly header-only today, either (a) add a new `sturm_uncompute` static lib in the root CMake and link it where needed, or (b) flip `uncompute_api` to header-only with `inline`. Decision left to the M3 implementer; document which was chosen in the commit message.

## Out of Scope (MVP)

Deferred to `docs/roadmap_transpiler_post_mvp.md`. In particular, **none** of the following are MVP work:

- Self-inverse ops (`^=`, `~`, `^`): **Phase A**.
- Constant arithmetic (`a += k`): **Phase B**.
- qint/qint arithmetic (`a += b`): **Phase C**.
- Comparison uncompute: **Phase D**.
- Compound expressions with named intermediates (`(b|c)&d`): **Phase E**.
- `WHEN` integration (`WHEN(expr) { ... }`): **Phase F**.
- Nested `WHEN` AND-fold retirement: **Phase G**.
- Classical control flow (`for`, `while`, `if` around quantum): **Phase H**.
- User-defined routine adjoints via `invert(foo)`: **Phase I**.
- IR-level optimizations (zero-ancilla fusion, peephole, hoisting): **Phase J**.
- Retirement of the legacy RAII uncompute layer: **Phase K**.

Any work item that turns up while executing MVP modules and does not fit the module it is in goes into a bd issue tagged with the appropriate post-MVP phase. Do not scope-creep modules.
